# WebUI 全局视觉与交互改造设计

## 背景

当前 WebUI 已经包含注册、账号、邮箱池、Codex、号池管理、自动补池和配置等多组能力，但各阶段叠加的样式和工具栏层级不一致。结果是页面信息密度高，却缺少清晰的导航、状态优先级和操作边界，重复使用时扫描成本较高。

## 目标

- 统一为浅色、专业的运维控制台风格，减少装饰性阴影和无意义的大块留白。
- 保留现有业务 DOM ID、API 路径、事件绑定和敏感字段遮罩，视觉改造不改变业务语义。
- 把页面分成“导航、页面标题、摘要、筛选、批量操作、数据区”六个稳定层级。
- 让注册、账号/Codex、邮箱池、号池管理、系统配置在桌面和窄屏下都能独立扫描和操作。
- 统一按钮、输入框、状态标签、表格、分页、弹层和提示的视觉语言，并让危险操作保持明确的红色语义。

## 视觉语言

- 页面背景使用冷白与浅灰，内容表面使用白色，边框使用低对比灰蓝色。
- 主色使用偏蓝的单色强调；成功、警告、失败分别使用绿、琥珀、红，不使用渐变背景或装饰性光晕。
- 卡片圆角控制在 6px 以内，阴影只用于弹层和悬浮菜单；普通页面区块使用边框分隔。
- 标题按页面级、区块级、字段级三级缩放，避免在紧凑工具区使用英雄式大标题。
- 交互控件保持稳定高度和宽度，表格使用固定列宽、粘性表头和横向滚动，避免动态内容撑开布局。

## 页面结构

1. 全局侧边导航：桌面显示图标、名称和当前页面状态；窄屏切换为顶部横向滚动导航。
2. 页面标题栏：显示当前模块名称、简短状态说明和右侧刷新/主要动作。
3. 摘要区：只放数量、健康度、运行状态等可快速判断的指标。
4. 工具区：搜索、日期、归档和列筛选放在同一筛选带，批量动作按业务域分组。
5. 数据区：表格、日志、进度和配置表单使用统一边框与间距。
6. 反馈层：Toast、确认弹窗、加载和空状态使用统一组件样式。

## 交互约束

- 不删除或重命名现有脚本依赖的 DOM ID；已有 API 参数和前端敏感字段请求逻辑保持原样。
- 不在列表中直接显示 access token、refresh token、密码、TOTP 等敏感值，只使用现有复制或一次性读取动作。
- 号池管理继续把健康、限流、错误分开统计；自动补池日志保持实时可见，并与巡检进度同一信息层级。
- 批量操作按钮仅在有选择项时启用；删除、归档、推送和修复等不可逆或有外部副作用的操作保留确认。
- 移动端优先保证导航、筛选、主要动作和表格首列可用，次要列通过横向滚动访问。

## 实现范围

- 本阶段只修改 `webui/templates/index.html` 的 CSS 和少量页面壳层标记。
- 不修改 Python、数据存储、SogouEdu API、Sub2API 健康判定或注册流程。
- 完成后使用 Node 进行内联脚本语法检查，使用 Playwright 在桌面和移动视口检查导航、各主模块、日志和表格是否溢出或重叠。

## 风险与回滚

- 单页模板包含大量历史样式，新增全局样式可能覆盖旧组件；使用命名空间和末尾覆盖层，保留原样式作为回退。
- 导航壳层若误改 `id` 或 `class` 可能导致现有初始化脚本失效；实现后对所有关键 ID 做静态检查并在浏览器中逐项打开。
- 视觉改造不改变后端接口，若出现布局问题可单独回滚本次模板提交，不影响已合并的业务代码。
